    rack-manager¶

    Where the site's hardware sits. rack-manager owns config/racks.json: the rooms, the racks, what is mounted where, the devices nothing can see, and the few cables nothing can see. It changes no device and no device record: a mount names a device as network-manager topology names it — a node, a switch, an access point, a machine, a device module, or a device recorded here — and only says where that device is.

    The console's Site › Physical tab draws it as racks with faceplates, the links the switches and LLDP see drawn port to port, through network-manager topology, which carries the racks resolved against the site.

    The record¶

    config/racks.json (schema: schemas/racks-fields.json):

    {
  "version": 1,
  "rooms": {
    "basement": { "displayName": "Basement" }
  },
  "racks": {
    "rack1": { "units": 42, "width": "19in", "numbering": "bottom-up", "room": "basement" }
  },
  "devices": {
    "ISP modem": { "kind": "modem", "model": "generic/isp-modem" },
    "patch1": { "kind": "patch-panel", "ports": ["1", "2", "…", "24"], "displayName": "Patch panel A" }
  },
  "mounts": {
    "tappaas1": { "rack": "rack1", "u": 10, "height": 2, "width": "full", "face": "front", "faceplate": "generic/server-2u" },
    "USW Pro XG 10 PoE": { "rack": "rack1", "u": 30, "height": 1, "width": "full", "face": "front", "faceplate": "unifi/usw-pro-xg-10-poe" },
    "patch1": { "rack": "rack1", "u": 32, "height": 1, "width": "full", "face": "front" },
    "ISP modem": { "room": "basement", "height": 1, "width": "half", "face": "front" }
  },
  "cables": [
    { "from": { "device": "USW Pro XG 10 PoE", "port": "5" }, "to": { "device": "ISP modem", "port": "LAN 1" }, "kind": "uplink", "label": "ISP hand-off" },
    { "from": { "device": "USW Pro XG 10 PoE", "port": "2" }, "to": { "device": "patch1", "port": "1", "side": "front" }, "kind": "patch", "origin": "seen" },
    { "from": { "device": "patch1", "port": "1", "side": "rear" }, "to": { "device": "tappaas2", "port": "enp97s0" }, "kind": "patch", "origin": "seen" }
  ]
}
    • u is the lowest unit a device takes, as the rack numbers its units; height is how many it takes. width is full, half or third of the rack, with a slot (its column, 0 at the left) for a half or a third. face is front or rear.
    • faceplate is a catalog key; unset, the view draws the catalog's suggestion for the device's model, else a generic plate.
    • rooms are where racks stand and where a device can stand loose. A rack's room names a room record; text that names no room yet is kept, and validate notes it. The building is the site's primary location (site-manager location show): neither a room nor a rack records one, and a building recorded before is dropped at the next write.
    • devices are the devices nothing can see — a modem, an ONT, a UPS, a patch panel (modem, ont, ups, patch-panel, other) — each with its catalog model or its ports. A recorded device is a device like any other: the topology lists it with its kind and ports, the console draws it, it can be mounted and it is a cable end.
    • A mount is in a rack (rack and u) or loose in a room (room, no rack, no unit).
    • cables are only what nothing can see: the ISP's modem, a patch panel, a PDU. A cable the switches or LLDP see comes from the topology and is never recorded. A device only a cable names is still placed by that cable, with its faceplate, and validate says how to record it (device add).
    • A patch panel's port has a side: its front (the default) and its rear each take one cable. A link split at a panel port (cable split) is two recorded segments marked with their origin — the link the topology sees, or a recorded cable — the device port to the panel port's front, the panel port's rear to the far end. The topology still carries one link between the two devices, with its segments and the panel port it runs through; the Physical view draws the two wires.
    • A passive plate nothing records (a PDU) can still be mounted under a name of its own with a passive faceplate.

    Verbs¶

    Verb Does
    validate [--topology <file>] [--json] The whole document: every mount names a device the topology knows or one recorded here, no two mounts overlap, each fits its rack, a loose mount's room exists, every faceplate key is in the catalog, every cable end names a port the topology, a record or the catalog has, a panel port carries one cable a side. It notes a rack's room that is not recorded, and a device only a cable names.
    room list\|show [<room>] [--json] The rooms, their racks and what stands loose in them.
    room add <room> [--display-name] [--description] A new room (in the site's building).
    room modify <room> --set <field>=<value>... --unset <field>... Its display name or description.
    room delete <room> An empty room (no rack names it, nothing stands loose in it).
    device list\|show [<device>] [--json] The recorded devices, their ports, where they are mounted.
    device add <device> --kind modem\|ont\|ups\|patch-panel\|other [--model <vendor/model>] [--ports <n> \| --port <name>...] [--display-name] [--description] A device the topology cannot see. Not a name the topology already has.
    device modify <device> --set <field>=<value>... --unset <field>... Its kind, model, ports (a count or a list), display name, description.
    device remove <device> Once it is unmounted and no recorded cable names it.
    rack list\|show [<rack>] [--json] The racks; one rack with its mounts.
    rack add <rack> [--units 42] [--width 19in\|10in] [--numbering bottom-up\|top-down] [--display-name] [--room] [--description] A new rack.
    rack modify <rack> --set <field>=<value>... --unset <field>... Any field but its name; --unset clears a text.
    rack delete <rack> An empty rack.
    mount list [--rack <rack>]\|show <device> [--json] What is mounted where.
    mount add <device> (--rack <rack> --u <n> \| --room <room>) [--height] [--width] [--slot] [--face] [--faceplate] [--label] [--description] A device into a rack, or loose into a room. A recorded device's plate is its model's or its ports'.
    mount modify <device> --set <field>=<value>... --unset <field>... A move (rack and u, slot, face, or room — out of the rack, loose in it) or its plate and label; --unset faceplate goes back to the suggestion.
    mount remove <device> The device leaves the rack or the room. A passive plate's recorded cables go with it; a recorded device keeps its own.
    cable list [--json] The recorded cables.
    cable add --from <device:port> --to <device:port> [--kind patch\|uplink\|power] [--label] [--from-faceplate\|--to-faceplate <key>] [--from-side\|--to-side front\|rear] A cable nothing can see; a side on a patch panel's port.
    cable remove <device:port> [--side front\|rear] The recorded cable on that port (on a panel, that side's).
    cable split <device:port> --via <panel:port> The link on that port — seen or recorded — through a patch panel port: two recorded segments, the port to the panel port's front, its rear to the far end. The panel port must be free on both sides.
    cable join <device:port> Undo a split, given the panel port or a device end of a segment: the link is the topology's again, or one recorded cable when it was one.
    faceplates list [--json] The catalog.
    faceplates show <vendor/model> [--device <name>] [--json] One plate as text, one line per port row; --device fills a generic plate from that device's ports, with their live state.
    export --json The document and the whole catalog: what network-manager topology reads.

    Every changing verb takes --check (show the result, change nothing), locks, checks the whole resulting document and writes it atomically; a change that would leave it invalid writes nothing. The verbs that name a device read the topology (network-manager topology --json --no-health --no-racks) unless --topology <file> hands one in; when it cannot be read, device names are not checked and a warning says so. rack delete, room delete, device remove, mount remove and cable remove are destructive (the console asks for the name).

    Recording a device only a cable names¶

    A cable recorded before devices could be (the ISP's modem, named only on its cable) keeps working; validate points it out. Recording the device keeps the cable as it is:

    rack-manager device add 'ISP modem' --kind modem --model generic/isp-modem --check
rack-manager device add 'ISP modem' --kind modem --model generic/isp-modem
rack-manager mount add 'ISP modem' --room basement      # or --rack rack1 --u 3

    The faceplate catalog¶

    faceplates/<vendor>/<model>.json, one plate each:

    {
  "vendor": "UniFi", "model": "USW Pro XG 10 PoE", "match": ["USWED77"],
  "kind": "switch", "units": 1, "width": "full",
  "rows": [
    [{ "name": "Port 1", "kind": "poe" }, …, { "name": "Port 11", "kind": "sfp+" }],
    [{ "name": "Port 2", "kind": "poe" }, …, { "name": "Port 12", "kind": "sfp+" }]
  ],
  "labels": [{ "text": "UniFi", "at": "left" }]
}
    • rows are the port rows top to bottom (null is a gap). A port's name is the controller's ("Port 11", "sfp-sfpplus1"); its id, the topology's, is the number of "Port N", else the name, unless given. kind is rj45, sfp+, sfp28, poe, console or power.
    • match lists the models and names the inventories report the device by: the catalog's suggestion for a device is the plate whose model or match is its model or name.
    • generic nics fills the plate from a node's NICs (its uplinks), ports from a switch's ports (odd over even). The generic plates are the suggestion for a device the catalog lacks: a node gets generic/server-2u, a switch generic/switch-1u.
    • passive marks a device nothing can see (patch panel, PDU, modem).

    A new model is a new file; faceplates show <key> checks it without the console.

    Lifecycle¶

    install.sh / update.sh build the flake package and link rack-manager into ~/bin; the package carries the catalog beside the compiled sources. test.sh is offline: the unit suite over hrossen's topology and the CLI against a temp config. validate.sh runs rack-manager validate.
