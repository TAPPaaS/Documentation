    Developing TAPPaaS¶

    This is the Develop track: everything you need to bring your own application onto TAPPaaS. If you're running a system, you want Operate; if you want the platform's concepts and design, that's What (capabilities, principles, design, ADRs).

    The one idea to hold on to¶

    Everything deployable is a module: a directory with a json contract (<module>.json — schema-checked, declares zones, sizing, dependsOn and the services it provides), the scripts the platform calls (install.sh, update.sh, test.sh), and its docs (README / INSTALL). In the taxonomy, your module is an App; it runs inside an Environment; managers operate it for the rest of its life.

    What the platform does with it¶

    The CICD mothership (tappaas-cicd) is the control plane — a VM that holds the git checkout and drives every module through the same lifecycle, fronted by the Module Manager:

    module-manager module add myapp        # create the VM, resolve dependsOn, run install.sh
module-manager module modify myapp     # release update: snapshot + test + merge
module-manager module test myapp       # run your test.sh — the same tests gate updates

    Updates then run unattended on the platform's schedule. Under the hood managers decide, controllers do — your module talks to the platform only through its json contract, never by hand-wiring firewalls or DNS. The full design is under What → Design: CICD Mothership and Git & Repository Topology.

    Start here¶

    1. Develop a Module — the quick start: from 00-Template copy to a shipped module.
    2. Module Details — the reference behind it: every file, field and convention of a module.

    Both are maintained with the template itself in the source repo (src/apps/00-Template/) and synced here at build time.
